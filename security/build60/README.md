# Build60 — Verified disposable database recovery drill (NOT production acceptance)

This build tests **actual `pg_dump -Fc` then `pg_restore`** between two *new*, isolated PostgreSQL 17 databases in a GitHub Actions service, using only invented UUIDs and synthetic invoice/candidate rows. It simulates source damage AFTER backup, and proves restored synthetic rows and audit digests match. It also tests restored row-level security, protected invoker view, anon denial, two recruiter owners, financial owner/role writes denied and both enabled invoice guard triggers. It restores ACLs and policies rather than silently passing `--no-acl` or `--no-owner`.

The runner refuses unless `GITHUB_ACTIONS=true`, `B60_DISPOSABLE_ONLY=yes`, `PGHOST=localhost`, `PGPORT=5432`, `PGUSER=postgres`, `PGDATABASE=postgres`. It does **not** connect to Supabase, use customer records, create hosted Auth users, merge or deploy. Postgres roles, test databases, files and snapshots are cleaned up with a trap.

**Release limitation:** A successful ephemeral backup and restore is **not** evidence of an actual production-equivalent encrypted backup, PITR, downtime, managed Postgres extension inventory, migration-specific roll-forward, data retention or a signed disaster-recovery acceptance. Those remain mandatory and separately authorized. No financial activation is permitted.
