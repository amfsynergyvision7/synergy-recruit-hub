# Build 85 — Core Candidate Data Access and AI Release-Hold Enforcement

**13 November 2026 | AMF Synergy Vision | Draft PR #12 | Production release HOLD**

## Engineering work actually completed in draft source

This build closes a **direct-call bypass** in lower-level server functions. Earlier Builds 82–84 added unconditional holds to six public server-function entry points, but those endpoints call exported AI and file-processing routines. A direct call from another trusted server module could previously perform CRM candidate reads, an external Gemini request, or a Drive download without invoking the endpoint-level release guard. Build85 adds the same hard-coded, non-environment-toggleable privacy hold at the data-access/provider boundaries.

1. **`src/lib/ai.server.ts`: seven new lower-level release checks.** The six exported operations `matchCandidatesToJob`, `matchCandidateResume`, `generateResumeSummary`, `extractCandidateFieldsFromResume`, `generateCandidateAtsScore` and `restructureResumeForClient` now begin with `assertExternalEffectReleased("candidate_ai_processing")` **before** any candidate/job data queries or provider calls. The shared private `callGeminiJSON` gateway independently enforces the same hold **before** reading `GEMINI_API_KEY` or preparing outbound network transmission. This protects direct internal usage and preserves the existing public-function guard, role checks, provider timeout and 512-KiB response cap.
2. **`src/lib/resume-fetch.server.ts`: two lower-level release checks.** `fetchResumeText` refuses access **before** even processing a saved candidate resume URL. `fetchDriveBytes` takes an explicit operation scope (default `candidate_ai_processing`; permitted alternative `drive_bulk_import`) and rejects with the matching hard-coded release hold **before** making the bounded remote request. This closes the raw file-ID direct-call path without allowing a generic override or environment toggle.
3. **`src/lib/drive-import.server.ts`: explicit scope forwarding.** The preexisting unconditional `assertDriveBulkImportReviewed()` stop is preserved. The importer's internal `fetchDriveBytes(file.id, "drive_bulk_import")` now supplies its operation type, so future independently reviewed privacy release can distinguish AI read access from drive bulk-import read access. No Drive import, parsing, provider request, or candidate write was executed.
4. **`src/lib/duplicates.server.ts` and `src/lib/duplicates.functions.ts`: double-checked candidate privacy.** The low-level `findDuplicateClusters(supabase, actorUserId)` now invokes `assertApprovedRole(actorUserId, ["admin"])` itself **before** scanning up to 5,000 candidate contact records. Its signed server-function caller supplies `context.userId` and maintains its own separate admin gate. This prevents a future server module from bypassing the role check merely by calling the exported scanning helper.
